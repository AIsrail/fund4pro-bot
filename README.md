# Grant & Business Plan Assistant — рабочая версия бота

Реализация по `TZ_Grant_Bizplan_Bot.md` + доработке от 02 сентября: red-flags
аудит, антиИИ-стиль на каждом шаге генерации, полный плейбук в промптах,
best-effort веб-поиск данных, Redis-опция, платёжная заготовка (выключена).

## Что реализовано

- Полный FSM-флоу, все состояния и переходы из ТЗ: intake организации →
  intake донора/инвестора (с попыткой скрапинга ссылки и ручным fallback) →
  определение идеи (свободный ввод или генерация 3-4 идей через LLM) →
  проверка наличия данных → диалоговое построение трёх деревьев (проблемы →
  цели → действия) → концепт с одобрением/правками → финальная версия (.docx)
  с лимитом в 2 итерации.
- Реальные вызовы Anthropic API (`claude-sonnet-5`) на каждом шаге, где
  нужна генерация текста.
- Реальная, но best-effort попытка скачать формы по ссылке на донора
  (requests-стиль GET + поиск .pdf/.doc/.docx ссылок на странице). Ничего
  не умеет обходить login wall/антибот/XFA-формы — в этих случаях просто
  возвращает пустой список и бот показывает кнопки ручного flow, как в ТЗ.
- Генерация .docx через простой markdown-парсер (`## заголовок`, `- пункт`,
  обычный абзац) — рабочий, но не брендированный шаблон.
- **Red-flags аудит (§1.2 плейбука)**: отдельный структурированный LLM-вызов
  (`llm.check_red_flags`) проверяет текст по всем 16 критическим ошибкам,
  возвращает JSON `{"passed": bool, "issues": [...]}`. Встроен в двух местах:
  - на уровне краткого концепта (Шаг 6) — лёгкая проверка, показывается как
    предупреждение под концептом, не блокирует переход дальше;
  - на уровне финальной версии (Шаг 7, и после каждой правки) — полная
    проверка, ДО отправки документа. При найденных проблемах бот сначала
    пытается автоисправить (до `RED_FLAG_AUTOFIX_ATTEMPTS` раз, по умолчанию
    1), а если не помогло — показывает проблемы пользователю с выбором
    "исправь сам" / "я пришлю правки", не отправляя документ. Проверка не
    расходует лимит `full_version_count`.
- **Антидетект-стилизация (§1.3)**: встроена как постоянная часть системного
  промпта (`llm.STYLE_GUARD_PROMPT`), применяется на КАЖДОЙ генерации текста
  (идеи, диалог по деревьям, концепт и его правки, финальная версия и её
  правки) — не отдельным проходом "почистить после", а изначально в каждом
  вызове.
- **Полный плейбук в системном промпте** (`llm.METHODOLOGY_PROMPT`): 7
  принципов, полная методология "3 деревьев" с правилом зеркалирования и
  фильтром приоритизации, бюджетные правила, донор-профили (USAID/EU/EBRD/
  UNDP/Aga Khan/GIZ) — не конденсат, а рабочая версия для генерации идей и
  документов.
- **Реальный веб-поиск** (`data_search.py`) при ответе "нет данных" на
  Шаге 4: best-effort через HTML-версию DuckDuckGo (без API-ключа). Если
  ничего не нашлось — явно помечает `project_data` как "оценка на основе
  международного бенчмарка" (не выдаёт молчаливую пустоту).
- **Redis-опция** (`bot.py::_build_storage`): если задан `REDIS_URL` в
  `.env` — состояния FSM переживают рестарт процесса. Если не задан —
  как раньше, `MemoryStorage`.
- **Платёжная заготовка (`payments.py`, ВЫКЛЮЧЕНА по умолчанию)**: реализован
  минимальный слой поверх Telegram Payments API (Telegram Stars "из коробки",
  без внешнего провайдера — либо замена на классический провайдер через
  `PROVIDER_TOKEN`). Включается одной переменной `PAYMENT_ENABLED=true` в
  `.env`; пока `false` — весь платёжный код не активируется, поведение
  идентично версии без оплаты (лимит просто скрывает кнопку правок).
  См. подробную инструкцию по активации в `config.py` и `payments.py`.

## Что осознанно НЕ реализовано в этой версии

- Оплата НЕ включена по умолчанию (см. выше) — активируется отдельно, когда
  будет готов провайдер.
- Донор-профили в промпте покрывают только основные (USAID/EU/EBRD/UNDP/
  Aga Khan/GIZ) — полный список из плейбука (частные фонды, страновые
  специфики) можно добавить по необходимости в `llm.METHODOLOGY_PROMPT`.
- Веб-поиск данных — best-effort через DuckDuckGo HTML, без гарантии
  качества результатов; для продакшена стоит подключить платный поисковый
  API (Tavily, Brave Search и т.п.) для надёжности.
- Автоисправление red-flags (`redflags:autofix`) сейчас упрощённо повторяет
  генерацию финальной версии целиком, а не патчит точечно найденные места —
  рабочее, но не самое экономное решение по токенам.

## Установка и запуск

```bash
cd grant_bizplan_bot
pip install -r requirements.txt
cp .env.example .env   # заполнить BOT_TOKEN и ANTHROPIC_API_KEY
export $(cat .env | xargs)
python bot.py
```

Хранилище FSM — `MemoryStorage` по умолчанию, либо `RedisStorage`, если
задан `REDIS_URL` (см. `.env.example`). Для продакшена рекомендуется Redis,
если бот будет перезапускаться часто или нужна персистентность между
рестартами.

### Включение оплаты (когда будет готово, ориентир — через месяц)

1. В @BotFather: `/mybots` → выбрать бота → `Payments` → подключить
   провайдера (для Telegram Stars ничего подключать не нужно — работает
   сразу).
2. В `.env`: `PAYMENT_ENABLED=true`, при необходимости `PROVIDER_TOKEN` и
   `PAID_VERSION_PRICE_XTR`.
3. Перезапустить бота — платёжная кнопка и инвойсы включатся автоматически,
   код менять не нужно.

```
├── bot.py                  # точка входа, сборка роутеров, выбор storage
├── config.py                # переменные окружения, лимиты, платёжные флаги
├── states.py                 # FSM-состояния
├── keyboards.py               # inline-клавиатуры
├── llm.py                     # промпты методологии + red-flags + антиИИ-стиль
├── docgen.py                   # markdown -> docx
├── donor_scrape.py              # best-effort скачивание форм донора
├── data_search.py                # best-effort веб-поиск статистики
├── payments.py                    # платёжная заготовка (выключена)
├── requirements.txt
├── .env.example
└── handlers/
    ├── start.py                    # Шаг 0: /start, выбор flow
    ├── org_info.py                  # Шаг 1
    ├── donor_info.py                 # Шаг 2
    ├── idea.py                        # Шаг 3
    ├── data_step.py                    # Шаг 4 (+ веб-поиск)
    ├── tree_building.py                 # Шаг 5 (+ лёгкий red-flags на концепте)
    ├── concept.py                        # Шаг 6
    ├── final_version.py                   # Шаг 7 (+ полный red-flags гейт)
    └── payments_handlers.py                # pre_checkout / successful_payment
```
